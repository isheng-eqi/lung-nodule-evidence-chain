# 三、7 个 MCP 工具

| 工具名 | 功能 | 何时被调用 |
|---|---|---|
| **`kg_consult_decision`** | **核心**：为肺结节患者推导处置建议，输出完整可溯源依据链（7 跳推理） | 需要判断"这位患者该怎么处理"时 |
| `kg_lookup_concept` | 查询本体概念的定义、层级、别名、尺寸约束 | 需要确认术语含义（如 mGGN vs pGGN）时 |
| `kg_get_clause` | 获取指定条款的完整内容与推理关系 | 已知条款编号，需展开详情时 |
| `kg_find_clauses_by_nodule` | 按密度类型 + 直径检索适用条款（不含完整推理） | 快速定位条款、做覆盖分析时 |
| `kg_get_ontology_summary` | 本体概览：类层次、条款数、标准对齐 | 说明知识来源与覆盖范围时 |
| `kg_list_clauses` | 列出全部 18 条推荐意见 | 确认能力边界时 |

**命名遵循官方 `mcp-builder` 规范**：统一前缀 `kg_` + 动作导向 + 只读工具标注 `readOnlyHint`。

# 五、★ 检索-推理双驱动架构（这是评分点）

```
                 用户提问："55岁男性，8mm混合磨玻璃结节，吸烟30年，怎么随访？"
                                        │
                    ┌───────────────────┴───────────────────┐
                    ▼                                       ▼
        ┌───────────────────────┐             ┌──────────────────────────┐
        │   检索（文本层）        │             │   推理（结构层）           │
        │   knowledge_base_search│             │   kg_consult_decision    │
        │   （Nexent 平台提供）   │             │   （本项目自研 MCP）       │
        ├───────────────────────┤             ├──────────────────────────┤
        │ 向量检索 ES 知识库      │             │ 本体匹配 → 条款定位        │
        │ 返回：条款原文片段      │             │ → 展开处置动作             │
        │                        │             │ → 多跳推导（7 跳）         │
        │                        │             │ → 禁忌判定                 │
        │                        │             │ → 分级诊疗归属             │
        └───────────┬───────────┘             └────────────┬─────────────┘
                    │                                       │
                    └───────────────────┬───────────────────┘
                                        ▼
                        ┌───────────────────────────────┐
                        │  智能体综合两者输出             │
                        │  · 处置建议（来自推理）          │
                        │  · 条款原文（来自检索）          │
                        │  · 完整依据链 + 条款编号         │
```

| 多跳推导 | ❌ | ✅ | ✅ |
| 条款级溯源 | 🟡 只能引用文档 | ✅ 精确到条款编号 | ✅ |
| 边界与禁忌 | ❌ | ✅ | ✅ |
| 拒答兜底 | ❌ 易编造 | ✅ | ✅ |

# 七、⚠️ 开发中踩到的一个坑（值得写进材料）

## 问题：HTTP 421 Misdirected Request

**现象**：MCP 服务在本机测试正常，但 Nexent 连接时报
```
httpx.HTTPStatusError: Client error '421 Misdirected Request'
for url 'http://nexent-mcp:8020/mcp'
```

**根因**：FastMCP 2.x 默认启用 **DNS 重绑定保护（DNS rebinding protection）**，
只信任 `localhost` / `127.0.0.1`。当 Nexent 以**容器服务名**（`nexent-mcp:8020`）
访问时，`Host` 头不是 localhost，被框架拒绝。

**修复**：显式配置传输安全策略

```python
from mcp.server.transport_security import TransportSecuritySettings

sec = TransportSecuritySettings(
    enable_dns_rebinding_protection=False,
    allowed_hosts=["nexent-mcp:8020", "localhost", "127.0.0.1", ...],
)
mcp.settings.transport_security = sec
```

**说明**：因本服务部署在隔离的 Docker 内网（`nexent_network`）、不暴露到公网，
放宽 Host 校验不引入额外攻击面。

**这个坑在官方文档里没有明确说明**，属于实战发现。

# 八、⭐ 还需要你完成的最后一步（界面操作）

**MCP 工具是"挂到 Agent 上"才在对话中生效的。** 服务端和平台侧都已就绪，
只差在界面上把它选给智能体。

## 操作步骤

1. 打开 **<http://127.0.0.1:3000>**，登录 `admin@<示例域>` / `<管理员密码>`

2. 左侧 **「智能体开发」→ 智能体配置 → 点开 `肺结节处置助手`**

3. 切到 **「工具与技能」** 标签页

4. 应该能看到 MCP 分组下的 **`lung-nodule-kg`**（或直接列出 `kg_` 开头的工具）
   - 若没看到，点 **「刷新」** 或重新进入页面

5. **勾选全部 7 个 `kg_` 工具**：
   ```
   ☑ kg_consult_decision
   ☑ kg_lookup_concept
   ☑ kg_get_clause
   ☑ kg_find_clauses_by_nodule
   ☑ kg_get_ontology_summary
   ☑ kg_list_clauses
   ```

6. **保留原有的 `knowledge_base_search`**（这是双驱动的另一半）

7. 在「使用要求」里追加一条，让 Agent 知道何时用哪个工具：
```
7. 优先调用 kg_consult_decision 获取带条款编号的处置依据链与推理路径，
   再调用 knowledge_base_search 检索条款原文作为补充。
   若 kg_consult_decision 返回 coverage=NOT_COVERED，
   必须如实告知"指南未覆盖，建议上级医院会诊"，禁止编造条款。
```

8. **保存 + 发布**

9. 回到调试窗口，重问那个问题：
   > 一位 55 岁男性，8mm 混合磨玻璃结节，吸烟 30 年，该怎么随访？

**期望**：回答中既有【推荐意见14】的条款依据，又有推理路径。
