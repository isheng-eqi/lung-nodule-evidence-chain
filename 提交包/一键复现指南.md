**可复算的数字**：


> **⚠️ 如实说明该工具的能力边界**（材料中同样如此陈述）：
> · **fatal 级悬空声称：0 条** —— 这一项是可靠的
> · **数字偏差：实测 0 条**（修正后）。此前版本曾报 5 条**已知假阳性** ——
>   例如把 `### 3.3 工具参数幻觉` 这一章节标题读成"声称工具数是 3"。
> · 根因：**"从自然语言散文里判断某句话是否在声称某个计数"没有定义**
>   （与 `skeleton_changed` 同类的判据问题）。
>   已通过"裸 `\s` → `[ \t]`"（禁跨行）与两条负向断言收紧，现为 0 条。
>
> **扫描器会先跑自检：4 条规则的正样本必须命中、负样本必须不命中；
> 自检不过则拒绝输出结论**（防止给出虚假的全清保证）。

## 7. ★ 最终验收核对（一条命令验证"证据齐全"）

```bash
cd 02_代码与本体/tools
# ⚠️ 从 tools/ 到包根是两层（本级已按实测修正）
python3 verify_evidence.py --pkg ../..
```

**作用**：把**正文里的 15 个关键数字**逐个回溯到 `03_验证与数据/` 的 JSON 来源，
报告是否一致。**返回码 0 表示全部一致**（可用于流水线）。

**本包实测输出**：

```
OK  模板文件总行数        = 1,135        OK  骨架函数行数       = 677
OK  领域参数函数行数      = 238          OK  DomainSpec 字段数  = 9
OK  肺结节规范处置 条款数 = 18           OK  固定资产贷款审查    = 61
OK  特种设备安全管理      = 102          OK  skeleton_changed   = None
OK  禁忌提示 A 双驱动     = 2/3          OK  禁忌提示 C 仅图谱   = 0/3
OK  术语覆盖率            = 82.7%        OK  MedRepBench        = 81.3%
OK  宽松判据              = 100.0%       OK  严格判据           = 80.0%
OK  严格+判据             = 21.8%

15/15 一致
```

> **若你跑出的结果与上表不同**，说明包内正文与 JSON 已经分叉 ——
> 请以 JSON 为准（它是脚本生成的），并运行 `inject_metrics.py` 修复正文表格。

### ⚠️ 这条命令的**证明力边界**（必须说明）

**它只做「正文 ↔ JSON」的交叉核对，不重算代码。**
因此它**发现不了「JSON ↔ 代码」的漂移** —— 例如
迁移成本 JSON 曾停留在 `1,120 / 662`，而同期的 `migration_cost.py`
重跑已得 `1,135 / 677`（本轮已修）。

**即：绿灯表示"文档与 JSON 自洽"，不表示"数字与代码自洽"。**
要覆盖后者，需另行重跑 `migration_cost.py`（第 2 节）并比对。

**我们选择把这条边界写出来**，而不是让一个绿色勾号承担它承担不了的证明责任。

**这正是本材料希望被检验的地方。** 若你的复算结果与随包 JSON 不一致，请对照：

| 可能原因 | 检查点 |
|---|---|
| 语料版本 | `04_参考资料/` 里的 `*_clean.txt` 是清洗后版本，字符数应在 `四份文档构建报告.json` 里有记录 |
| Python 版本 | 部分脚本用了 3.11+ 的 `X \| None` 类型语法 |
| 是否联网 | **以上脚本全部离线运行**，不访问任何外部服务 |

**其它材料索引见 `00_提交包说明.md`。**
