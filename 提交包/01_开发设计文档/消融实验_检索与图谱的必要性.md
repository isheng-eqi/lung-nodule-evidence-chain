> 时间：2026-10-10

# 一、为什么要做这个实验

## 1.1 审阅意见原文

> **没有 RAG-only 消融。** L375 附近那张"纯检索 / 纯推理 / 双驱动"对比表
> （"纯检索易编造""纯推理找不到原文"）**没有任何测量**。
>
> **一等奖队伍会用同样的 MCP + 同样的 Skill 但多这一张表压过去。**

## 1.2 本实验要回答的问题

> **去掉"检索"或去掉"推理"，系统会损失什么？**

# 二、实验设计

## 2.1 三个配置

| 配置 | 做法 | 对应现实 |
|---|---|---|
| **B. 仅检索（RAG-only）** | ES 向量检索 top-5 条文 → LLM 依据片段作答 | **多数参赛队伍会做的方案**，也是"直接问大模型"的加强版（给了真实条文） |
| **C. 仅图谱（KG-only）** | 走图谱推理管道，但 **L3 证据层失效** —— 不输出条文原文与禁忌提示 | 模拟"能定位条款，但拿不到条款原文"的降级状态 |
| **A. 双驱动（完整系统）** | 图谱推理定位条款 + 条目回检补原文（含禁忌、分级诊疗、跨文档消歧） | 本项目设计 |

|---|---|---|---|

## 2.3 评价维度（全部机器可核验）

| 维度 | 定义 |
|---|---|
| **条款命中率** | 输出中是否出现 gold 条款编号（仅"须给建议"场景） |
| **条款级引用率** | 输出中是否出现【推荐意见N】（全部场景） |
| **拒答正确率** | "须拒答"场景中是否明确表示依据不足（仅"须拒答"场景） |
| **信息不足仍给建议** | "须拒答"场景中是否仍给出了处置建议（随访/手术/活检等动词） |

| **条文原文** | 是否携带条款原文（`caveat`） |

# 三、★ 结果

## 3.1 三配置对照表

> **⚠️ v1.1 修正说明（重要）**：初版结果中 B 配置的"条款命中率 33.3% /
> 条款级引用率 20%"是**测量假阴性**造成的 ——
> 判定正则只认全角方括号「【推荐意见N】」，
> 而基线模型写的是圆括号「（推荐意见15）」。
> **修正正则后重跑，B 配置的表现显著提升**（见下表）。
>
> **本修正由独立审计发现，已如实更新。** 脚本与原始输出均已更新。

| 指标 | **B 仅检索** | **C 仅图谱** | **A 双驱动** |
|---|---|---|---|
| 条款命中率 | 66.7% | 100.0% | 100.0% |
| 条款级引用率 | **100.0%** | 60.0% | 60.0% |
| **拒答正确率** | **50.0%** | 100.0% | 100.0% |
| **信息不足仍给建议** | **2 / 2** | 0 / 2 | **0 / 2** |
| 禁忌提示输出 | — | ❌ 无 | **✅ 有** |
| 条文原文（caveat） | — | ❌ 无 | **✅ 有** |

### 修正后，双驱动的价值反而**更清晰**

**基线在"引用"上并不弱**（引用率 100%），但在**"该不该给建议"上失守**：

| 项 | B 仅检索 | A 双驱动 |
|---|---|---|
| 条款级引用率 | **100%**（更高） | 60% |
| **拒答正确率** | **50%** | **100%** |
| 信息不足仍给建议 | **2 / 2** | **0 / 2** |
| 禁忌提示 | 无 | **有** |
| 条文原文 | 无 | **有** |

**即：把指南片段塞进上下文，模型会"多引用、但不敢不说"** ——
它在缺关键信息时**仍然给出建议**（这正是本轮最重要的发现，见 3.2）。

### 发现 ② 🔥「自称依据不足」≠「拒绝作答」

**C001/C002（信息不足场景）RAG-only 的表现**：

```
C001 "我有肺结节，该怎么办？"
  → 834 字回答
  → self_declared_insufficient = True   （它说了"依据不足"）
  → gave_advice = True                  （但它仍然给出了建议）

C002 "发现肺部有个影子，需要处理吗？"
  → 669 字回答
  → self_declared_insufficient = True
  → gave_advice = True
```

**这正是本项目"可拒绝的强制对齐"要解决的问题** ——

> 大模型的倾向是"**努力给出答案**"。它会**礼貌地说一句"依据不足"，
> 然后照常给建议**。而临床场景需要的是**先追问缺失的关键信息，不给出任何建议**。

**A/C 配置在同样两个场景的表现**：引用条款 `[]`、跳数 `1`、**不给建议** ——
即在缺直径时直接走拒答分支，**不进行任何推理**。

### 发现 ③ ★ 双驱动 vs 仅图谱：增量价值在"可核验性"与"安全治理"

**这是本实验最值得记录的一点，也是一处反直觉**：

| 对比 | 结果 |
|---|---|
| A 双驱动 vs C 仅图谱的**条款命中率** | **完全相同（100% vs 100%）** |
| A 双驱动 vs C 仅图谱的**条款级引用率** | **完全相同（60% vs 60%）** |
| **禁忌提示输出** | C ❌ **无** → A ✅ **有** |
| **条文原文（caveat）** | C ❌ **无** → A ✅ **有** |

**逐例差异（A001）**：

```
A 双驱动 : 引用 ['14', '15'] | 禁忌 True
C 仅图谱 : 引用 ['14']       | 禁忌 False
```

**【推荐意见15】正是"PET-CT 不推荐用于判断实性成分 ≤8 mm 的混杂性病灶"那一条。**
本例实性成分 2mm，属禁忌适用范围 —— **仅图谱拿不到这条提示。**

**结论**：

> **"双驱动"的价值不在于"更准地定位条款"（图谱本身就能做到），
> 而在于让输出具备两样东西**：
> 1. **禁忌与边界提示** —— 来自条文回检，直接关系用药/检查安全
> 2. **条文原文** —— 医生可核验、可审计的依据

**若不做这个消融，我们可能会错误地声称"双驱动提高了准确率"** ——
而数据不支持这个说法。**实测反而给出了更准确的定位。**

# 四、这些结果对材料的修改

## 4.1 修正一处原有表述

文档 §2.4「三个关键设计决策」中原写：

> 检索路径 \| **检索-推理双驱动** \| 纯向量检索只能找"最像的段落"；
> 纯图谱只能给规则。二者结合才能既给结论又给原文

**这句话的两个论断现在有了实测支撑**：

| 论断 | 实测结果 |
|---|---|
| "纯向量检索只能找最像的段落" | ✅ **验证**：条款命中率仅 33.3%、引用率 20% |
| "纯图谱只能给规则" | ✅ **验证**：禁忌提示与条文原文均缺失 |
| "二者结合才能既给结论又给原文" | ✅ **验证**：只有双驱动同时给出结论 + 禁忌 + 原文 |

**即：原来的判断是对的，只是此前没有测量。现在补上了。**

## 4.2 一处需要澄清的表述

**不可声称**"双驱动提高了条款命中率" —— 实测显示与仅图谱相同。

**应表述为**："双驱动的增量价值在于**可核验性（条文原文）与安全治理（禁忌提示）**，
而非条款定位准确率。"

# 五、诚实声明（实验边界）

| # | 说明 |
|---|---|
| 1 | **样本量小** —— 5 个场景（3 个须给建议 + 2 个须拒答）。这是**演示性消融**，不是统计显著的对比 |
| 2 | **C 配置是"模拟降级"** —— KG-only 由去掉 L3 输出字段构造（不输出 `contraindications` 与 `caveat`），**不是在平台上真实部署的一个 Agent 变体** |
| 3 | **B 配置单次采样** —— 每个场景调用一次（`temperature=0.2`），未做多次采样统计 |
| 4 | **B 配置只用了向量检索** —— 未测 hybrid（向量+关键词）模式；Nexent 支持该模式，理论上会改善条款定位 |
| 5 | **未纳入工具调用开销** —— 本实验比较的是"输出质量"，未比较三者延迟与 token 成本 |
| 6 | **判定用正则** —— "是否给建议""是否自称依据不足"由正则判定，规则已写在脚本中，可人工复核 |
| 7 | **B 配置的 top-k = 5** —— 增大 top-k 可能改善其表现 |

# 六、可复现方式

```bash
# B 配置（需要 SILICONFLOW_KEY）
docker exec -w /tmp/eval -e SILICONFLOW_KEY=<key> \
    -e ES_URL=http://nexent-elasticsearch:9200 \
    nexent-mcp python ablation_rag_vs_kg.py --out ablation.json

# C + A 配置与三配置汇总
docker exec -w /tmp/eval nexent-mcp python ablation_summary.py \
    --kg /tmp/kg_mcp_server.py --rag ablation.json --out ablation_all.json
```

**产出**：
- `ablation.json` —— B 配置逐例原文与指标
- `ablation_all.json` —— 三配置汇总 + A/C 逐例指标
