# 三、★ 截图 4：Skill 真实生效的证据

## 3.1 提问

```
一位55岁男性，8mm混合磨玻璃结节，实性成分2mm，吸烟30年，该怎么随访？
```

## 3.2 Reasoning 面板（智能体的判断过程）

```
步骤 1
The user asks about a 55-year-old male with 8mm mixed ground glass nodule,
solid component 2mm, smoking 30 years, follow-up advice.
Diameter is provided (8mm). So we can proceed.

There's a skill: lung-nodule-decision. Must load it first.

思考：用户提供了结节最大径（8mm）、密度类型（混合磨玻璃）、实性成分（2mm）
及危险因素（吸烟30年），信息完整，可直接进入处置决策流程。
此请求与 lung-nodule-decision 技能描述高度匹配，须先加载技能指南。
```

## 3.3 ★★★ 实际执行的代码

```python
代码：
skill_content = read_skill_md("lung-nodule-decision")
print(skill_content)

▶ Executed code  (PYTHON)
   skill_content = read_skill_md("lung-nodule-decision")
   print(skill_content)
```

## 3.4 这段证据为什么重要

它证明了**三件事**：

| # | 证明 | 说明 |
|---|---|---|
| **1** | **Skill 的描述被平台正确加载并用于判断** | 智能体说"此请求与 lung-nodule-decision 技能描述高度匹配" |
| **2** | **智能体主动决定加载 Skill** | "必须加载技能指南"，而非被动接受注入 |
| **3** | **Skill 内容被实际读取并用于后续决策** | 执行了 `read_skill_md()` 并打印内容 |

**这是 Nexent 渐进式 Skill 披露机制的工作过程**：
Skill 的元数据（名称 + 描述）常驻上下文用于匹配判断，
命中后才加载完整的 SKILL.md 内容 —— 这正是官方设计的用意。

**对比**：如果只截图最终回答，无法证明 Skill 起了作用；
这张图展示了"**判断 → 决定 → 加载**"的完整链路。

# 五、采集方法（可复现）

使用 `agent-browser` CLI 自动化操作 Web 界面：

```bash
# 1. 打开页面
agent-browser open http://127.0.0.1:3000

# 2. 查看可交互元素（获得 @eN 引用）
agent-browser snapshot -i

# 3. 登录
agent-browser click @e20                    # 登录账户
agent-browser fill @e23 "admin@<示例域>"
agent-browser fill @e24 "<管理员密码>"
agent-browser click @e22                    # 登 录

# 4. 进入智能体
agent-browser open http://127.0.0.1:3000/zh/agents
agent-browser click @e31                    # 编辑「肺结节处置助手」

# 5. 查看工具与技能
agent-browser click @e40                    # 工具与技能标签
agent-browser screenshot 02_工具与技能.png

# 6. 进入调试并发问
agent-browser click @e32                    # 调试
agent-browser fill @e75 "一位55岁男性，8mm混合磨玻璃结节，实性成分2mm，吸烟30年，该怎么随访？"
agent-browser click @e80                    # 发送
agent-browser wait 40000
agent-browser screenshot 03_调试问答.png

# 7. 关闭
agent-browser close
```

**说明**：`agent-browser open` 会阻塞终端，需在后台 job 中执行。
