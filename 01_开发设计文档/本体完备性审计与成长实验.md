# 本体完备性审计与成长实验（含一处指标缺陷的修正）

> 实验时间：2026-10-10
> 目的：把"本体构建效率优势"从**自证指标**改为**可被外部核验的指标**
> 脚本：`kg-service/ontology_coverage_audit.py`、`kg-service/ontology_growth_experiment.py`

---

# 一、🔴 先说一个必须修正的指标缺陷

## 1.1 原指标的表述

本项目此前（以及材料中）使用：

> **本体对齐率 = 100.0%**，**人工介入率 = 0.0%**

并把它作为"半自动化本体构建效率优势"的核心证据。

## 1.2 这个指标的问题

查 `ontology_builder.extract()` 的实现，抽取逻辑是：

```python
def _match_classes(self, body: str, parent_filter: str) -> list[str]:
    # 1) 找出所有命中的概念及其在文本中的首次位置
    hits: dict[str, int] = {}
    for cls, meta in self.onto["classes"].items():   # ← 只遍历本体里已有的类
        ...
```

**它只在本体里找概念。** 因此：

| 后果 | 说明 |
|---|---|
| 抽取出的对象三元组**天然全部对齐** | 因为候选集本身就是本体 |
| `unaligned_rate` **恒为 0** | 分子永远为 0 |
| 候选池**恒为空** | 人工审核闭环**从未被触发** |
| **极小的本体也报 0% 未对齐** | 实测：仅 8 个类的本体同样报 0.0% |

## 1.3 结论：这是一个**自证式指标**

**它测的是"抽取器只认本体"，不是"本体是否完备"。**

`unaligned_rate` 只在一种情况下会大于 0：
`_match_classes` 从**别名**命中了某类，但该类的规范名不在索引中 —— 而这种情况在本实现里不会发生。

## 1.4 为什么必须主动修正

| 若不修正 | 后果 |
|---|---|
| 材料里写"对齐率 100%" | 评审若读代码，会发现这是**同义反复** |
| 声称"人工介入率 0% 体现了自动化优势" | 实际是**审核闭环从未触发**，不是自动化好 |
| 被追问"未对齐的怎么办" | 答"候选池"→ 追问"池子里有过东西吗"→ 答不上来 |

**这比"对齐率低"更伤** —— 因为它涉及指标的可信度。

**本项目选择主动修正，并给出替代指标。**

# 二、✅ 替代指标：语料侧的本体覆盖率

## 2.1 设计思路

要让度量**不依赖本体**，候选术语就必须**从语料侧发现**。

`ontology_coverage_audit.py` 的做法：

```
① 从语料中挖掘"规范术语形状"的片段（规则透明、可复核）
     · 中文医学/规范术语高频后缀（结节、随访、活检、治疗、征、
       检测、评估、筛查、诊断、干预、转诊、人群、因素、病史…）
     · 取后缀前 2~5 个中文字符
     · 只保留出现 ≥2 次的（单次出现更可能是噪声）
② 逐个判断该术语能否被本体对齐（调用 builder.align()）
③ 覆盖率 = 已覆盖候选数 / 候选总数
④ 缺口清单按频次排序输出
```

**关键**：候选集**不由本体产生**，因此覆盖率不会天然为 100%。

## 2.2 实测结果

```
本体类数: 52
候选术语最小频次: 2

文档                 候选术语     已覆盖     缺口      覆盖率
--------------------------------------------------
2024共识               83      58     25    69.9%
2025共识               30      20     10    66.7%
筛查2023               27      19      8    70.4%
筛查2025               33      19     14    57.6%
--------------------------------------------------
合计                  173     116     57    67.0%
```

**术语覆盖率 67.0%** —— 这才是"低资源领域"的真实起点。

> **此前材料里的"100% 对齐"与本处的"67% 覆盖"并不矛盾**，
> 但它们说明的是**完全不同的事**：
> · 100% 对齐 = 抽出来的东西都能挂到本体上（**内部一致性**）
> · 67% 覆盖 = 语料里的术语有三分之一本体里没有（**外部完备性**）
>
> **材料中必须同时给出这两个数，并说明各自含义。**

# 四、⚠️ 一个已知技术局限：缺中文分词

## 4.1 现象

缺口清单里有约 20 个**切分残留**，例如：

```
治中国专家共识      ← "诊治中国专家共识" 被截断
工智能辅助诊断      ← "人工智能辅助诊断" 被截断
当进入临床治疗      ← 跨词边界
节的个体化评估      ← 跨词边界
国农村肺癌筛查      ← 跨词边界
```

## 4.2 根因

**当前术语发现用的是"后缀 + 前 N 字"的正则启发式，没有中文分词。**

因此：
- 会切出跨词边界的片段
- 也会**漏掉**不以高频后缀结尾的真实概念

## 4.3 影响评估

| 方面 | 影响 |
|---|---|
| 覆盖率数值 | 分母（候选数）偏大 → **覆盖率被低估** |
| 缺口清单 | 混入噪声 → 需要人工筛选 |
| 漏检 | 不以高频后缀结尾的概念不会被发现 |

**即：67.0% 是一个偏保守（偏低）的下界估计。**

## 4.4 为什么仍然可用

- 规则**完全透明**，任何人都能复核每个候选是怎么来的
- **漏检方向明确**（偏保守），不会高估自己
- 真实概念与噪声**可人工区分**（如第 3 节所做）

**局限已如实记录，不掩盖。**

# 五、本体成长实验：为什么"未对齐率下降"无法演示

## 5.1 实验设计

三条路径处理同一批 4 份文档：

| 路径 | 说明 |
|---|---|
| **A 冷启动** | 每份文档都用初始种子本体（52 类），本体不成长 |
| **B 增量成长** | 处理后把候选概念回灌本体，再处理下一份 |
| **C 最小种子** | 从 8 类开始，观察本体能否被带大 |

## 5.2 实测结果（三条路径**全部 0.0% 未对齐**）

```
文档             A 固定52类      B 增量52类      C 最小种子(8类)
2024共识             0.0%          0.0%          0.0%
2025共识             0.0%          0.0%          0.0%
筛查2023             0.0%          0.0%          0.0%
筛查2025             0.0%          0.0%          0.0%
```

**本体规模：路径 B 52 → 52 类（未增长）；路径 C 8 → 8 类（未增长）**

## 5.3 结论：这个实验**证伪了自己**

**"未对齐率随本体成长而下降"这个预期无法演示** —— 因为该指标恒为 0（见第 1 节）。

**实验的价值在于暴露了指标缺陷，而不是产出一条漂亮的曲线。**

## 5.4 修正后的表述

材料中**不应**写"未对齐率随本体成长下降"（这是未经验证的预期）。

**应写**：

> 项目的 `ontology_builder` 设计了候选概念池与人工审核闭环
> （`pending_concepts` + `review()`/`reject()` 接口），
> 但**在本批 4 份文档上该闭环未被触发** ——
> 原因是抽取器的候选集来自本体自身，因此不存在"对齐失败"的对象。
>
> 真实的完备性缺口需要**语料侧度量**才能发现（见覆盖率审计）：
> 实测术语覆盖率 **67.0%**，识别出 **20 个真实领域概念缺口**。
> 该闭环的实际触发需要把**语料侧发现的缺口**接入候选池 —— 这是下一步工作。

# 八、这轮迭代的价值

## 8.1 表面上是"退步"，实质是"补上了最容易被击穿的一环"

| 之前的说法 | 现在的说法 |
|---|---|
| 对齐率 100% | 内部一致性 100% + **外部完备性 67%** |
| 人工介入率 0%（暗示自动化好） | 人工介入率 0%（**本批文档未产生对齐冲突**）+ **20 个本体缺口** |
| 未对齐率随本体成长下降 | **该指标恒为 0，机制已实现但未触发** |

**从"看起来完美"变成"看起来可信"。**

## 8.2 在竞争中的意义

**参赛作品普遍会给出漂亮指标。** 差异在于：

- 有些队伍**不知道**自己的指标是自证的
- 有些队伍**知道但不说**
- **主动指出自己指标缺陷、并给出替代度量的，极少**

**而且这次修正顺带产出了一个真正的技术发现**：
初版种子本体偏向"已检出结节如何处置"，**遗漏了整个筛查维度**（37 次高频词）。

**这是一个真实的本体设计盲区，也是"低资源领域本体构建"的典型问题** ——
比任何编造的"完美指标"都更有说服力。
