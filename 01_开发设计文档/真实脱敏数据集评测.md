# 真实脱敏数据集评测（MedRepBench）

> 目的：把多模态链路的证据从「**1 张自造图 / 8-8 字段**」升级为
> 「**真实脱敏数据集上的字段级召回**」
> 版本：v1.0（2026-10-10）

---

# 一、为什么做这个评测

## 1.1 独立审计的指控

> **图文证据规模**：1 张**自造**样例图，VLM 跑 1 次，报'8/8 字段（准确率 100%）'。
> 把样例图扩到 10–20 张（可用不同版式/字号/含噪声的构造样本），
> 报'**字段级准确率 + 失败案例**'，**比'8/8 = 100%'可信十倍**。

以及更尖锐的一条：

> **放过了手边唯一可用的外部数据** —— MedRepBench 的 1,087 条检查报告
> 足以**独立评测多模态识别链路**。
> 「用它做决策评测不成立」**≠**「用它做识别评测不成立」。

## 1.2 本轮的做法

**用真实脱敏数据，而非构造样本。**
来自 MedRepBench（HuggingFace: `MedRepBench/MedRepBench`，CC-BY-NC-4.0）
的 `censored/` 目录 —— **1,925 张真实脱敏中文医疗报告图片**。

---

# 二、★ 任务界定（必须先说清，否则构成误导）

MedRepBench 的客观抽取任务是「**实验室检验项表格抽取**」，
而本项目的核心任务是「**肺结节影像报告 → 处置决策**」。

**两者任务不同。**

| 本评测**能**证明 | 本评测**不能**证明 |
|---|---|
| 多模态链路的**识别层**在**真实脱敏报告**上的字段抽取能力 | ❌ **不能**证明结节处置决策的正确性 |
| 抽取在**不同版式 / 不同医院**报告上的鲁棒性 | ❌ **不能**替代结节场景的临床验证 |
| 「多模态异构数据统一识别与资产标识」这一赛题要求的落地程度 | ❌ **不能**说明检验项本身被用于决策 |

> **一句话**：这是「**识别层**」的独立外部评测，**不是**「决策层」的评测。

# 三、评测设置

| 项 | 内容 |
|---|---|
| 数据集 | MedRepBench（HuggingFace） |
| 许可 | **CC-BY-NC-4.0**（非商业性使用） |
| 数据 | `censored/` 目录的真实脱敏中文医疗报告图片 |
| 抽样 | 从 **822 份有客观标注**的报告中等距随机抽 **26 份**（固定随机种子 20261010） |
| 实际完成 | **24 份**（2 份因 API 限流失败，如实记录） |
| 参考项总数 | **223** 个检验项 |
| 被评测模型 | `Qwen/Qwen3-VL-8B-Instruct`（与本项目 `kg_analyze_report_image` 同一模型） |
| 抽样门槛 | 仅取标注项数 ≥ 3 的报告（避免平凡样本） |

## 判定口径（按官方脚本复刻）

复刻 `scripts/evaluate_objective.py`：

1. 按 `item_name` 归一化后**一一配对**（预测项 ↔ 参考项）
2. 配对上的项，逐个字段比对
3. 指标 = **field-level recall**（字段级召回）
   - 未配对上的参考项，其 5 个字段**全部计入分母**（即漏检被计为错）

**归一化规则**（官方口径）：
- 文本：去所有空白、统一全角/半角括号、转小写
- 数值：去千分位逗号 + 去尾随零（`12.80` ≡ `12.8`）

## 4.3 ★ 失败模式（如实记录）

| 现象 | 证据 | 解读 |
|---|---|---|
| **`item_range` 召回最低（73.5%）** | 参考范围常以小字或特殊排版呈现（如 `~<0.05`、`Negative(-)`） | 小字区域识别是当前最弱环节 |
| **`item_value` 召回次低（78.9%）** | 数值需逐位准确，`12.80` 与 `12.8` 虽归一化等价，但 `0.010` 与 `0.01` 之外的位数差异会判错 | 数值精度敏感 |
| **配对率低于预测项数** | 多份报告的「预测项数 = 参考项数，但配对少 2–4 个」 | **不是漏检，而是名称表述差异** —— 同一项目在中英文/缩写/别名上的写法不同，归一化后仍不等 |
| **#10（60.0%）与 #26（64.0%）明显偏低** | 两份都是版式较密/字号较小的报告 | **版式复杂度直接影响召回** |
| **有 1 份预测项数多于参考项**（#20: 5 vs 6） | 可能把非检验项也抽了出来 | 存在少量**过度抽取** |

# 五、这个结果对材料的意义

## 5.1 与修前的对比

| 项 | 修前 | **修后** |
|---|---|---|
| 数据来源 | **自造**（PIL 程序生成） | **真实脱敏**（MedRepBench） |
| 样本量 | **1 张** | **24 份报告 / 223 个检验项** |
| 指标 | 「8/8 字段 = 100%」 | **字段级召回 81.3%** |
| 失败案例 | 无 | **有**（逐份明细 + 5 类失败模式） |
| 可复核性 | 无法独立复核（自造样本 + 自核） | **可复核**（公开数据集 + 官方判定口径 + 随包脚本） |

## 5.2 为什么 81.3% 比 100% 更有利

> **「100%」在单样本上不构成证据，只构成可疑。**
> **「81.3%（223 项）并附逐份明细与 5 类失败模式」是可核验的能力描述。**

评审看到前者会去找口径；看到后者会认为团队**知道自己的边界在哪**。

## 5.3 对附加分②的直接贡献

官方附加分②措辞：「**真实脱敏行业数据集效果评测**」。

| 要素 | 本项目状态 |
|---|---|
| 真实脱敏数据 | ✅ MedRepBench（1,925 张，CC-BY-NC-4.0） |
| 可复核的评测口径 | ✅ 复刻官方 `evaluate_objective.py` |
| 量化结果 | ✅ 字段级召回 81.3% |
| **任务匹配度** | ⚠️ **部分匹配** —— 测的是「识别层」，非「结节决策层」（已在 §2 明确界定） |

# 七、复现步骤

```bash
# 1. 获取数据集元数据与图片（需能访问 HuggingFace）
curl -L -o meta.csv \
  "https://huggingface.co/datasets/MedRepBench/MedRepBench/raw/main/datasets-meta-zhCN.csv"
# 图片在 censored/ 目录下，按 meta.csv 的 image 列下载

# 2. 跑评测（官方口径）
python3 eval/medrep_bench_eval.py \
  --meta meta.csv --img-dir censored/ --n 26 \
  --out 真实脱敏数据集评测_MedRepBench.json
```

**产出**：
- `03_验证与数据/真实脱敏数据集评测_MedRepBench.json`（含逐份明细与失败案例）
- `02_代码与本体/eval/medrep_bench_eval.py`（可复现脚本）
