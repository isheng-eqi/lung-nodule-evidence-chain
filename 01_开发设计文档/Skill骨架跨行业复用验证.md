# Skill 骨架跨行业复用验证（实验记录）

> 实验时间：2026-10-10
> 目的：用**可复现实验**替代"我们的方案可以跨行业"这类声称
> 脚本：`skill/skill_template.py`（可复现）

---

# 一、为什么做这个实验

## 1.1 官方评分措辞（两处点名）

> **(25%) 智能体编排与 MCP/Skill 深度集成**
> …模块**解耦性、扩展性强**，**适配多行业场景迭代需求**

> **(25%) 系统交互体验与能力沉淀**
> …明确规划**可复用 Skill 工作流模板**沉淀方案，具备**通用推广价值**

## 1.2 此前证据的缺口

本项目已有**抽取流水线层**的迁移验证（`workflow_template.py`，医疗 + 金融）。

**但"Skill 工作流模板"是编排层的东西，不是抽取层。**

**仅凭"我们的 Skill 分了三层、可以替换本体"，不足以支撑"模块解耦性、扩展性强"。**
评审完全可以问："你怎么证明替换一层不影响其他层？"

## 1.3 本实验要回答的问题

> **换一个行业，Skill 到底要改多少、不用改多少？**

# 二、实验设计

## 2.1 把 Skill 拆成两类槽位

| 类别 | 含义 |
|---|---|
| **骨架槽位** | 跨领域保持不变的结构：分层表、执行流程四步、输出格式四段、约束编号体系、工具选择表、错误处理表、拒答协议 |
| **领域槽位** | 换领域必须替换的值：领域名、领域对象、必需事实、分类主轴、处置轴、分级轴、工具名、知识库索引、术语示例、示例输出 |

## 2.2 实验方法

```
① 写一个**不含领域分支**的渲染函数 render_skill(spec)
      —— 结构（章节顺序、表头、流程步数、约束编号）与领域无关
② 定义两个 DomainSpec（医疗 / 金融）
③ 同一函数渲染两份 SKILL.md
④ 逐章节、逐行比对，量化"改了多少"
```

**关键约束**：`render_skill()` **不因领域而分支** ——
这是"骨架未改动"的可核验前提。若函数里有 `if industry == "medical"`，
实验就不成立。

## 2.3 为什么选医疗 + 金融

与抽取层的迁移验证**保持同一对领域**，形成**两层证据的可对照**：

| 层 | 验证对象 | 脚本 |
|---|---|---|
| 数据平面 | 抽取流水线 | `workflow_template.py` |
| **控制平面** | **Skill 编排** | **`skill_template.py`（本实验）** |

# 三、实验结果

## 3.1 总体指标

```
医疗领域字符数      : 2,844
金融领域字符数      : 2,817
章节总数            : 9
逐字相同的章节      : 1  (11.1%)
★ 结构相同的章节    : 9/9  (100%)
★ 逐行相同比例      : 77.7%
```

**9 个章节结构全部相同；77.7% 的行逐字相同。**

## 3.2 逐节比对

| 章节 | 医疗 | 金融 | 判定 |
|---|---|---|---|
| 前言（frontmatter） | 526 | 510 | 结构同 |
| 分层编排结构 | 328 | 345 | 结构同 |
| 工具选择规则 | 238 | 245 | 结构同 |
| 执行流程 | 775 | 777 | 结构同 |
| 拒答示例 | 41 | 43 | 结构同 |
| 硬性约束 | 248 | 243 | 结构同 |
| 示例 | 140 | 110 | 结构同 |
| 输出格式 | 221 | 217 | 结构同 |
| **错误处理** | **236** | **236** | **逐字相同** |

## 3.3 ★ 一个意外发现：唯一逐字相同的章节是「错误处理」

**236 → 236 字符，一字不差。**

**为什么**：错误处理表编码的是**编排协议层的失败模式**：

| 错误 | 原因 | 解决方案 |
|---|---|---|
| `coverage=NOT_COVERED` 且 `missing_fields` 含必需项 | 描述缺少必需事实 | 向用户追问 |
| 概念归一化返回 `matched=false` | 术语不在本体中 | 用 `available_concepts` 重试 |
| 条款展开返回 `found=false` | 条款编号不存在 | 用 `available_clauses` |

**这些失败模式与行业无关** —— 它们是"一个知识图谱驱动的决策技能"
在协议层必然遇到的三种情况，无论行业是医疗还是信贷。

**这揭示了一个机制**：**编排协议是领域无关的抽象**，而非领域知识。

## 3.4 领域无关行的分类统计

| 类别 | 行数 |
|---|---|
| **编排层协议**（`coverage` / `traceable` / 字段名 / `NOT_COVERED`） | **13** |
| 章节结构（标题 / 表头） | 19 |
| 约束编号体系 | 6 |
| 分层意图与骨架说明 | 3 |
| 工具调用约定（参数约束） | 2 |
| 错误处理表 | 2 |

## 3.5 实际变化的内容（62 行 / 139 行）

```
name:                    lung-nodule-decision → credit-risk-decision
allowed-tools 工具名:      kg_consult_decision → kg_consult_credit_decision
                         kg_lookup_concept    → kg_lookup_term
                         kg_find_clauses_by_nodule → kg_find_clauses_by_profile
description:             肺结节规范处置…      → 信贷风险审查…
tags:                    medical/lung-nodule → finance/credit-risk
DomainSpec 字段值:        必需事实 / 分类主轴 / 处置轴 / 分级轴 / 术语示例 / 示例输出
```

**全部是"注入的值"，没有一处是"改结构"。**

# 四、★ 结论：编排层领域无关，只有数据平面随领域变

## 4.1 一句话表述

> **换领域时，Skill 的「控制平面」（编排协议、分层结构、约束体系、
> 错误处理、拒答协议）完全不变；只有「数据平面」（工具名、领域术语、
> 分类轴、分级轴）被替换。**

## 4.2 用分层图表示

```
┌─────────────────────────────────────────────────┐
│  控制平面（领域无关，100% 复用）                   │
│  · 三层编排结构（事实层 / 推理层 / 证据层）          │
│  · 执行流程四步骨架                                │
│  · 输出格式四段结构                                │
│  · 约束编号体系（1~7 条 + 领域附加）                 │
│  · 工具选择规则的判定维度                            │
│  · 错误处理协议（三种失败模式）                       │
│  · 拒答协议（缺必需项 → 追问，不猜测）                │
├─────────────────────────────────────────────────┤
│  数据平面（随领域替换）                             │
│  · 工具名 / 知识库索引                              │
│  · 领域对象 / 必需事实 / 分类主轴 / 处置轴 / 分级轴    │
│  · 领域术语与示例                                   │
└─────────────────────────────────────────────────┘
```

## 4.3 这解决了什么

| 官方措辞 | 本实验的回答 |
|---|---|
| "模块**解耦性**强" | 控制平面与数据平面分离，**替换数据平面不动控制平面**（9/9 章节结构不变） |
| "**扩展性**强" | 新增一个行业 = 新增一个 `DomainSpec` 实例，**不修改渲染逻辑** |
| "适配**多行业**场景迭代需求" | **Skill 层**为医疗 + 金融两领域实测（抽取层已扩到医疗/金融/制造三领域，见「工作流模板沉淀方案」章）；四个可迁移行业分析见「工作流模板沉淀方案」章 |
| "可复用 **Skill 工作流模板**" | 模板 = `render_skill()` 函数 + `DomainSpec` 契约 |
| "具备**通用推广价值**" | 迁移成本 = 填写一个 DomainSpec，无需改动编排结构 |

# 五、诚实声明（实验边界）

| # | 说明 |
|---|---|
| 1 | **金融领域的工具是"假定存在"的** —— 本实验验证的是**Skill 编排结构的可迁移性**，不是"金融版 Skill 已在平台上跑通"。医疗版是**真实挂载并运行**的（平台上 skill_id=1） |
| 2 | **本实验与抽取层迁移验证使用同一对领域**（医疗 + 金融），便于两层证据对照；但金融侧在两层都是样例/假定数据 |
| 3 | **"结构相同"的判定基于形状指纹**（行数 / 表格列数 / 编号项数），不是语义等价性证明 |
| 4 | 该实验证明**"骨架可复用"**，**不证明"迁移到新领域后效果同样好"** —— 后者需要该领域的真实规范与评测集 |

# 六、可复现方式

```bash
# 生成两领域 Skill 并比对
python3 skill/skill_template.py --validate --out skill_migration_report.json

# 单独导出某一领域
python3 skill/skill_template.py --emit finance --out SKILL_finance.md
python3 skill/skill_template.py --emit medical --out SKILL_medical.md
```

**产出**：
- `skill_migration_report.json` —— 结构化比对报告（含逐节明细）
- 两份 SKILL.md —— 可用于人工核验
