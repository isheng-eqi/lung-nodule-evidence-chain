### P8 ★ 关键代码解读（1/2）

**代码 1：主推荐句 / 注意事项切分**（这是最有技术含量的一段）

```python
# 问题：条款正文含限定语，例如【推荐意见14】：
#   "……如果混杂性结节增大或实性成分增多，通常提示为恶性，
#     需考虑切除，而不是非手术活检……"
# 若一并抽取，会把"外科手术根治性切除"错挂到随访条款上，
# 导致系统把"随访"条款误读成"建议手术" —— 即把过度诊疗自动化。

CAVEAT_MARKERS = ["随访中需注意", "需注意", "注意事项", "如果", "若"]

def _split_main_and_caveat(text):
    """把条款正文拆成「主推荐句」与「注意事项」"""
    for marker in CAVEAT_MARKERS:
        idx = text.find(marker)
        if idx > 0:
            return text[:idx], text[idx:]
    return text, ""

# 处置动作只从主推荐句抽取；注意事项中的禁忌单独抽为 contraindicatedFor
```

**讲解要点**：这不是一个技术难点，而是一个**安全性设计** ——
抽取规则的错误会导致**临床上的过度诊疗**。

**代码 2：否定表述检测**

```python
NEGATION_PATTERNS = ["无", "不", "未", "否认", "没有", "非", ...]

def _has_negation(text, keyword_pos, window=6):
    """在阳性关键词前方 6 字符窗口内检测否定词"""
    start = max(0, keyword_pos - window)
    return any(p in text[start:keyword_pos] for p in NEGATION_PATTERNS)

# 效果："无吸烟史" 不再被误判为 "有吸烟史"
#       条款命中率 82.2% → 100.0%
```

### P13 ★ 三层拒答机制（安全设计的亮点）

「可拒绝的强制对齐」需要三层齐备：

| 层 | 机制 | 实现位置 |
|---|---|---|
| 第 1 层 引擎层 | 判断 `coverage`，无匹配条款时返回 `NOT_COVERED` | MCP 推理引擎 |
| 第 2 层 编排层 | 提示词强制"缺关键信息必须追问" | Agent 约束提示词 |
| 第 3 层 表现层 | 追问时列所需信息、给选项 | 输出格式约束 |

**并讲一个真实故事**：

> 我们通过批量验证发现："我有肺结节，该怎么办？"这个信息不足的问题，
> 系统竟然调用了 18 次工具、耗时 59 秒、输出 2728 字试图硬答。
>
> 排查后发现：**引擎层有拒答能力，但编排层没有强制约束**。
> 补上约束后 —— 工具调用 18→0 次，耗时 59→3.5 秒，改为**结构化追问**。

**这个"发现问题→定位→修复→量化"的闭环，比直接声称"我们做了拒答"更有说服力。**

**PPT 页标题**：`十七、自测评测与诚实边界`

**左右对照表**（这是本页的核心）：

| 本评测能证明 | 本评测不能证明 |
|---|---|
| 条款定位：能否找到正确条款 | 临床有效性 —— 需真实数据与伦理审批 |
| 阈值判定：≤ / > 边界是否正确 | 安全性 —— 需前瞻性研究 |
| 溯源完整性：是否携带条款编号 | 真实病例覆盖 —— 用例仍属构造 |
| 拒答行为：信息不足时是否追问 | 医生决策改善 —— 需对照实验 |
| 跨文档一致性：四份文档 100% 对齐 | 长期稳定性 —— 需持续运行观测 |

**收尾一句**：**"这是条款一致性测试，不是临床效果验证。"**

> **讲解要点**：这一页的作用是**主动划边界**。
> 评委若听到我们主动说"这不能证明临床有效性"，会认为我们**懂行且诚实**；
> 若等评委问出来才承认，效果相反。

**讲解要点（约 1 分钟，逐句）**：

1. **开场点题**："前面都是我们自评。这一页回答一个更本质的问题 ——
   **这些问题直接问大模型不就行了？**"

2. **讲实验设计**："同一批 6 个临床问题，分别交给两条通路。
   左边是裸大模型，系统提示词只给角色，不给任何指南内容；
   右边是我们的完整系统。"

3. **讲三个数字**（不要念全表）：
   - "**条款级溯源：0 比 6**"
   - "**命中中国共识条款：0 比 6**"
   - "**信息不足时，裸模型直接作答，我们追问**"

4. **讲最有力的那个例子**（放慢语速）：
   "15mm 混杂性磨玻璃结节，裸模型建议**直接胸腔镜手术切除**。
   而中国共识要求**先 3 个月重复 CT**。
   **更关键的是** —— 文献荟萃分析显示，部分实性结节的过度诊断率是 31%、
   亚洲人群 38%，而且**37.1% 的切除病灶其实是原位腺癌或非典型腺瘤样增生**。
   **本例正是部分实性结节加亚洲患者，裸模型的建议方向恰好指向文献所警示的那一端。**"

5. **主动说边界**（这一步很关键）：
   "需要说明的是，**裸大模型并非全错** ——
   有一个场景它引对了中国指南，并正确提示了 PET-CT 不适用。
   **我们证明的是可核验性与口径一致性的差异，不是'裸模型不可用'。**"

6. **收口**："所以本项目的价值不是'做得比大模型好'，
   而是**把看起来专业的回答，变成可核验、可审计、口径统一的依据链**。"

> **为什么这一页最重要**：它是整场答辩里**唯一用外部对照而非自评**来论证价值的一页。
> 评委可以质疑我们的评测集，但很难质疑"同一个问题两条通路的输出差异"。

# 四、5 分钟问答的准备

## 4.1 高频问题预判（按可能性排序）

### Q1：你们的创新点是什么？和直接问大模型有什么区别？

**答**：我们做了对照实验，用数据回答这个问题（见 P19）。

同一批 6 个临床问题，分别交给**裸大模型**（DeepSeek-V3，无知识库/无图谱/无工具）
和**本系统**：

| 维度 | 裸大模型 | 本系统 |
|---|---|---|
| 【推荐意见N】条款级溯源 | **0/6** | **6/6** |
| 命中中国共识期望条款 | **0/6** | **6/6** |
| 分级诊疗 / MDT / CAC | **0/6（全缺）** | 均输出 |
| 免责声明 | **0/6（全缺）** | 6/6 |
| 信息不足时 | 直接作答 | **追问** |

**三处最实质的差异**：

1. **随访间隔不符共识** —— 8mm mGGN，裸模型给"每 6 个月复查 × 2 年"，
   共识是"3、6、12、24 个月"
2. **跳过"先复查"直接建议手术** —— 15mm mGGN，裸模型建议"胸腔镜手术切除"，
   共识要求**先 3 个月重复 CT**
3. **信息不足仍作答** —— 问"我有肺结节该怎么办"（无直径），裸模型直接科普并给间隔

**诚实补充（很重要）**：裸大模型的回答**并非全错** ——
有一个场景它引对了中国指南并正确提示了 PET-CT 不适用。
**差异在于可核验性、口径一致性与追问行为**，而非"知识多寡"。

**这个补充必须主动说**：如果说"裸模型完全不可用"，任何懂行的评委一试就知道不成立。

### Q1b（追问）：那个 15mm 的例子，为什么说裸模型的建议有问题？

**答**：因为方向指向了**过度诊疗**。

裸模型建议直接胸腔镜手术切除。而中国共识【推荐意见15】要求：

> mGGN >8mm 者，**建议 3 个月重复胸部 CT**，持续存在者经评估后才考虑
> 非手术活检和（或）手术切除。

**更关键的是**：文献荟萃分析（Int J Cancer 2025，26 项研究）显示
**部分实性结节过度诊断率 31%、亚洲人群 38%**，且
**37.1% 的切除病灶是原位腺癌或非典型腺瘤样增生**（Acad Radiol 2026）。

**本例正是部分实性结节 + 亚洲患者** —— 裸模型的建议方向**恰好指向文献所警示的那一端**。

**两条独立证据（一次 API 调用 + 一份荟萃分析）指向同一结论** ——
这正是本项目在算法层做"防止把随访误读为手术"设计的现实依据。

### Q2：本体的 57 个类是怎么来的？有没有专家参与？

**答**：**诚实回答**：

- 类来自**指南条款的系统化梳理**，不是凭空定义
- 种子本体由我们根据共识的类目结构人工定义（52 类），后补充 5 个细化类
- **没有临床专家深度参与** —— 这是本项目的局限
- 但设计上有**人工审核闭环**（`pending_concepts` 候选池），
  实际部署时可由临床专家审核

**主动承认局限比掩饰更可信。**

### Q3：怎么保证抽取的知识是对的？

**答**：三层保障。

1. **强制对齐**：抽出的概念必须能对齐到种子本体，否则不入库
2. **可溯源**：每条三元组都记录来自哪条条款（`r1` 字段）
3. **可拒绝**：对齐失败即拒答，不编造

**并给出量化证据**：四份文档 100% 对齐率、人工介入率 0%。

### Q4：为什么不用 Neo4j？为什么自己写图谱服务？

**答**：**平台约束下的主动选择**。

- Nexent 在 `sdk/pyproject.toml` 中把 `neo4j`、`chromadb` 等依赖统一禁用为 `999.0.0`
- 我们没有试图绕过平台约束，而是采用**自研轻量三元组 + MCP 协议挂载**
- **这个约束反而带来好处**：图谱服务成为**独立可复用的组件**，
  不绑定特定图数据库

### Q5：只做了肺结节一个领域，怎么证明能迁移？

**答**：**用实验证明，而非声称**。

- 用**同一套代码骨架**跑了医疗（真实语料）与金融（样例语料）
- **`DomainSpec` 是唯一的领域参数入口（9 个字段）；`PipelineRunner` 等骨架类在本次迁移中未被编辑**（可人工核对的事实陈述，非自动判定的指标 —— 该判据与判定对象同文件，构成自指，见 `_verify_skeleton_unchanged` 注释）；本次只替换了种子本体与领域语料
- 并分析了四个行业的**文档形态共性**：都是「条款化规范 + 阈值条件 + 处置动作」

**并诚实说明**：金融用的是样例语料，验证的是骨架复用性。

### Q6：评测集是自己造的，怎么保证客观？

**答**：**金标准来自条款本身，不依赖标注者主观判断**。

- 每条用例的期望条款，是共识**明确写出**的（如"孤立性 mGGN ≤8mm → 【推荐意见14】"）
- 58 条用例分六类（覆盖抽样 / 边界 / 拒答 / 禁忌 / 分级诊疗 / 临床常见值）
- 生成脚本随代码提交，**任何人可重新生成**

**但必须承认边界**：

> 这是**条款一致性测试**，不是临床效果验证。
> 能证明条款定位、阈值判定、溯源完整性、拒答行为；
> **不能证明临床有效性与安全性** —— 那需要真实临床数据与伦理审批。

### Q7：PET-CT 那条禁忌是怎么处理的？

**答**：这是**条件化禁忌判定**，不是简单的关键词匹配。

共识说"PET-CT 不推荐用于判断**实性成分 ≤8mm 的混杂性病灶**"。
系统会把这个条件与患者事实匹配：

> "PET-CT 不推荐用于判断实性成分 ≤8mm 的混杂性病灶；
> **本例实性成分 2mm，属该禁忌范围**。"

**并展示验证结果**：8 个场景中，该禁忌只在**正确场景**出现（mGGN 场景），
不在纯磨玻璃结节与实性结节场景误报。

### Q8：系统的响应速度如何？生产环境能用吗？

**答**：**给出实测数据**。

| 场景类型 | 平均工具调用 | 平均耗时 |
|---|---|---|
| 典型正例 | 3.4 次 | 9.8 秒 |
| 信息不足（追问） | 0 次 | 3.5 秒 |

**并说明**：当前跑在单机 Docker Compose 上（13 个容器），
生产部署可按院内服务器规格扩容。

### Q9：如果指南更新了，系统怎么跟上？

**答**：这是「**可进化**」的设计要点。

```
新文档进入
    ↓
自动抽取 → 强制对齐
    ↓
对齐成功 → 直接入库
对齐失败 → 进入候选池（pending_concepts）
    ↓
人工审核
    ├── 通过 → 扩充本体（版本号 +1）→ 重新对齐
    └── 驳回 → 记录并丢弃
```

**关键指标：未对齐率** —— 设计意图是"随本体成长而下降"。

> ⚠️ **如实说明**：实测在本批语料上**该指标恒为 0**，因为种子本体已覆盖全部对象属性 —— **机制已实现、未触发**。
> **我们不把它当作"本体在进化"的证据。**
> 完备性缺口由**语料侧独立审计**发现（术语覆盖率 82.7%，143/173）。

**答**：**能，且已准备可复现脚本**。
