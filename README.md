## 这个项目解决什么

医生面对一份 14 页的专家共识，要在 3 分钟内判断一个 8mm 混杂性磨玻璃结节该随访还是该手术。
**规范里写了，但没人能边翻边看病。**

本项目把规范文档加工成知识资产，让智能体给出**带条款依据**的处置建议，
并**主动提示禁忌**（例如"PET-CT 不推荐用于判断实性成分 ≤8mm 的混杂性病灶"）。

**关键主张**：**双通道（检索 + 图谱）的价值不在"答对哪一条"，
而在"不遗漏必须提醒的那一条"。** 有消融实验数据支撑（见下）。

## 核心结果（全部可复算）

| 维度 | 结果 |
|---|---|
| 三行业规范 → 条款 | 医疗 **18** / 金融 **61** / 制造 **102** 条 |
| 对象三元组 | 64 / 96 / **190** |
| 术语覆盖率 | **67.0% → 82.7%**（143/173，⚠️ 提升主要来自分词改进，**不等于本体成长**） |
| 端到端命中率 | **100%**（宽松）/ **80%**（严格判据） |
| 真实脱敏数据集 | MedRepBench 字段级召回 **81.3%**（223 项） |
| 统一资产标识 | **7/7 一致**（注册表与台账共用同一清单） |

### 消融实验：双驱动到底带来什么

| 指标 | A 双驱动 | C 仅图谱 | B 仅检索 |
|---|---|---|---|
| 条款命中率 | **100%** | **100%** | 67% |
| **禁忌提示覆盖** | **2/3** | **0/3** | 0/3 |
| **信息不足仍给建议** | **0** | 0 | **2** |

**A 与 C 的命中率完全相同** —— 所以我们**不声称**"双驱动提高了准确率"。
但**只有双驱动能带回"不该做什么"**：禁忌来自原文的 CAVEAT 段落，图谱三元组里没有。

## 架构

```
文档（文本 / 表格 / 图文）
      │
      ▼
[清洗] clean_corpus.py
      │
      ▼
[本体] ontology_builder.py  ← 半自动化：抽不到就入候选池，不硬塞
      │  62 类 / 双领域关系
      ▼
[抽取] 受约束抽取 + 强制对齐
      │  条款 / 对象三元组 / 数据属性
      ▼
[双通道]  ┌── 图谱通道：MCP 工具（7 个）
          └── 检索通道：Elasticsearch（4 份文档 / 236 分块）
      │
      ▼
[推理] PipelineRunner（骨架类，跨领域复用）
      │  跨文档多跳 + 语境消歧
      ▼
[输出] 结论 + 条款编号 + 禁忌提示 + 免责声明
```

**跨领域复用**：换行业只改 `DomainSpec`（**9 个字段**），骨架类不动。

## 七项自查（防止"看起来对"）

本项目在迭代中**主动推翻过自己 8 个指标**：

| 指标 | 最初 | 现在 |
|---|---|---|
| `unaligned_rate` | 恒 0 | **已废弃**，改用外部度量 |
| `alignment_rate` | 恒 1.0 | **降级为"非对齐证据"** |
| 类目命中率 | 100% | **85.7%**（分母改为全部类目） |
| 端到端命中率 | 100% | **100% / 80% 双报** |
| 可溯源率 | 恒真 100% | **93.1%**，并披露**与覆盖率同源** |
| `skeleton_changed` | 硬编码 False | **`None`（承认不可测）** |
| `strict_plus` | 未披露 | **21.8% 主动披露** |

**已知边界**（详见 `01_开发设计文档/` 附录 A）：

- 条款一致性测试 **≠ 临床效果验证**
- **0 位医生试用**
- 运行态可寻址条款 **23 条**（离线构建 103 条）；金融/制造未进运行态
- 知识资产本地化，**但推理走外部 API，患者描述文本会出网**
- 本体"持续动态更新"**机制已实现但未触发**（种子本体已覆盖全部对象属性）
